# ADR 0004: 원본 서식 참조를 사용하는 DOCX 문단 계획

상태: 제한된 문단 구조 편집에 채택. native 호환성 승격 보류.
날짜: 2026-11-05. 관련 이슈: #83, #85, #96.

## 문제

기존 run 텍스트 교체만으로 문단 분리·병합·이동을 표현할 수 없습니다. 입력칸에
LF만 허용하면 실제 문단과 화면 줄바꿈이 달라집니다. 매 Enter마다 저장하면
입력 지연·실패 중 잠금과 원격 ID 교체가 계속 발생합니다.

## 결정

지원되는 연속 문단 범위에 원본 문단·run의 서식 참조와 결과 순서를 지정하는
`replace_paragraphs`를 추가합니다. 브라우저가 초안 전용 ID로 여러 입력·구조
변경을 합치고 명시적 저장 때 하나의 리비전으로 확정합니다. 서버는 모든 참조·
부모 경계·보호 구조·예상 텍스트·크기와 겹침을 검증한 뒤 원본 part의 범위만
교체합니다. 타깃 밖 XML과 다른 part는 재직렬화하지 않습니다.

문단 복제 시 원본 namespace와 서식은 유지하되 고유 문단 ID는 한 번만 사용합니다.
run을 다른 문단에 옮겨도 원래 namespace scope를 함께 운반합니다. 문단 병합의
문단 서식은 앞 문단을 따르고 run 직접 서식은 원본을 따릅니다. LF는 run 안
`w:br`로 표현하고 새 문단과 구분합니다.

## 대안

- 매 구조 키 입력마다 서버 commit: 입력·composition·초안과 원격 revision의
  경합이 커지므로 채택하지 않습니다.
- 문서 전체를 외부 편집 엔진으로 변환·저장: 미지원 part·참조 보존의 증거가
  없어 이번 단계에 도입하지 않습니다.
- 임의 HTML을 저장 계약으로 사용: 브라우저 DOM 구조를 OOXML 의미로 오인하고
  서식·보안 경계를 흐리므로 사용하지 않습니다.

## 제약과 후속 작업

구역·명시적 페이지 경계·필드·주석·북마크·opaque XML은 이번 계획에서 보호합니다.
run·문단을 넘는 선택, 모바일 실제 IME 인증, 안정적인 AI anchor와 서버 undo는
#85, #86, #90, #96에서 확장합니다. 구조 초안과 다른 revision의 과거 AI 표시는
현재 위치로 추정하지 않습니다. 데이터 내용과 인증 정보는 진단에 기록하지 않습니다.

native fixture·Word 수정 저장·재열기 증거가 없으므로 #83 전체 완료 또는
production 승격을 주장하지 않습니다. 기본 텍스트 편집을 포함한 기존 경로와
새 구조 경로의 회귀·실패 검사를 함께 유지합니다.
