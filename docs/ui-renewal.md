# 문서 편집 UI 개선

전체 추적: #41. 커밋 지침: #39, PR #40.

## 문제와 작업 순서

| 순서 | 이슈 | 확인한 문제 | 완료 기준 |
| --- | --- | --- | --- |

각 기능은 해당 테스트·설명·변경 이력을 함께 독립 커밋으로 기록합니다. 전체 변경은
공통 디자인에 의존하므로 하나의 통합 PR에서 기능별 커밋을 검토할 수 있게 합니다.
서로 다른 도구·문서 개선을 한 커밋에 묶지 않습니다.

## 디자인 기준

Image Gen으로 만든 XLSX와 DOCX 전체 화면 reference를 기준으로 합니다. concept은
실제 화면에 사용하는 raster asset이 아니며 저장소 밖에 보관합니다. 실서비스 UI는
Solid와 semantic HTML로 구현합니다.

- 흰색 header·toolbar, slate-100 작업 바탕, slate-900 본문, indigo-600 강조색
- slate-200 divider, 6px control radius, 44px 이상 touch target
- 공통 header: 제품명·문서명·형식, 저장 상태, 활동 버튼
- 형식별 toolbar: 지원하는 동작만 표시하고 unavailable 상태는 명확히 구분
- 본문: spreadsheet engine 또는 문서 용지. 오른쪽 활동 rail은 접을 수 있게 구성
- 알림: 본문을 가리지 않는 inline 안내. 실패·충돌·미저장 상태를 조용히 숨기지 않음
- 문서 text·서식·표는 원본 내용을 표시하며 concept 예시 데이터를 문서에 주입하지 않음

concept에서 강조한 title 크기는 원본 서식과 다를 수 있으므로 문서 본문에 임의의
heading 서식을 적용하지 않습니다. 페이지처럼 보이는 용지는 읽기 배치이며 native
pagination을 뜻하지 않습니다. 원본 보존과 controller의 저장 권위는 유지합니다.

## 감사 기준

keyboard·focus 표시와 복귀, 의미 있는 label, live status, 긴 제목·오류 줄바꿈,
축소 모션, touch target, 모바일 overflow, 큰 문서 표시 비용을 검사합니다.
문서 텍스트는 HTML로 해석하지 않습니다. 활동에 인증 토큰을 보관하지 않습니다.

## 검증

기능별 Solid DOM·controller 검사와 실제 browser의 저장·reopen·복구를 확인합니다.
최종 검사는 `make verify web-test compatibility-test package-test package-smoke`를
사용합니다. 실제 호스트와 native Office 검증은 실행된 범위만 주장합니다.

## XLSX 도구

서식과 이력은 수식 입력줄 위의 도구 모음에서 실행합니다. 도구 모음은 시트를
열 때부터 표시됩니다. 실행 취소와 다시 실행은 서버에서 확인한 이력을 사용하며,
저장 중이거나 복구가 필요할 때는 비활성화합니다. 붙여넣기나 AI가 한 번에
저장한 변경은 한 작업으로 되돌립니다. 편집기를 그대로 열어 둔 채 시트만 갱신하고
선택했던 범위와 가로·세로 스크롤 위치를 유지합니다.

미리보기 범위 전체를 대조할 수 있고 값이나 수식만 바뀌었으면 기존 캔버스에서
변경된 셀만 갱신합니다. 서식이나 구조 변경은 시트 교체로 반영합니다.

Delete 또는 Backspace로 선택 셀의 내용을 지우면 한 작업으로 저장합니다.

| 시나리오 | 기대 결과 | 검증 |

| 실시간 알림이 먼저 도착하거나 확정 리비전이 바뀜 | 화면을 한 번만 교체하거나 복구 안내 표시 | 자동 테스트 |

## DOCX 읽기 배치

문단 경계의 명시적 페이지 나눔마다 별도 용지를 표시합니다. 원본의 run은
그대로 사용하고 내용 길이에 따른 자동 페이지 매김은 계산하지 않습니다. 입력은
포커스 시 경계를 표시합니다. 큰 문서의 본문 block은
content-visibility로 표시 비용을 줄이고 저장 전까지 같은 입력 node를 유지합니다.

## 문서 활동

최근 60개의 현재 연결 활동만 메모리에 보관합니다. 작성자·작업 위치·관찰 시각·
확인된 리비전을 표시합니다. 쓰기 응답이 불확실하면
완료로 표시하지 않습니다. 재열기 뒤 빈 목록은 이전 작업이 없었다는 뜻이 아닙니다.

## 알림과 복구

호환성 안내는 기본 접힌 inline row로 표시하고 오류는 확장 상태로 알립니다.
필수 복구는 닫아 숨길 수 없습니다. 초안 폐기 확인의 취소·Escape는 다시 불러오기
버튼으로 focus를 돌리고 명시적 복구 뒤에는 본문 또는 남은 오류로 이동합니다.

## 한국어와 원본

설치된 동일 버전의 Univer OSS 한국어 locale를 사용합니다. 알려진 호환성 feature와
연결·충돌 메시지만 한국어로 안내합니다. 알 수 없는 원인·기능은 원문을 남기고,
사용자 문서 text와 formula는 번역하거나 치환하지 않습니다.

## 입력과 접근성

DOCX의 붙여넣기는 차단하지 않습니다. 미지원 문자·줄바꿈·탭 또는 제한을 넘는
입력은 내용과 focus를 유지한 채 field 오류와 저장 전 안내로 표시합니다. 수정하면
바로 저장 가능 여부를 다시 계산합니다. 서버 검증은 그대로 최종 권위를 가집니다.
공통 헤더·toolstrip은 safe area와 touch target을 유지하고 활동 rail은 좁은 화면에서
본문을 덮지 않는 전환 surface로 표시합니다.

## 최종 확인 결과

- `make verify web-test compatibility-test package-test package-smoke` 통과.
  Node 검사 31개, Solid DOM 검사 10개와 Go 전체·race·vet, Python 회귀,
  XLSX corpus 및 패키지 검사를 포함합니다.
- 실제 browser에서 XLSX 선택 뒤 굵게·기울임·14pt 저장과 재열기,
  MCP AI 수정 반영을 확인했습니다.
- 실제 DOCX에서 본문·표 저장, 잘못된 줄바꿈 입력의 보존과 저장 차단,
  AI 동시 저장 시 초안 보존, 폐기 취소의 focus 복귀, 명시적 재불러오기를
  확인했습니다.
- 1536×1024 desktop, 1280×800 laptop, 390×844 mobile 크기를 점검했습니다.
  laptop과 mobile의 문서 전체 가로 overflow가 없고, 표·grid는 내부에서
  스크롤하며 활동 panel을 닫은 뒤에도 편집 surface가 유지됩니다.

시각 기준과 구현 비교:

| 기준 | 구현과 확인 |
| --- | --- |
| 공통 상단 구조 | 흰 헤더, 파일명, 저장 상태, 활동 진입점을 두 형식에서 통일 |
| 도구 위계 | 수식 입력줄 위에 이력과 서식 도구 모음 한 줄 |
| 문서 읽기 | 회색 배경과 흰 용지, 입력 focus에서만 본문 경계 강조 |
| 활동 영역 | 오른쪽 rail과 좁은 화면의 전환 surface, 현재 연결의 실제 활동만 표시 |
| 안내와 오류 | 문서 위 inline 안내, 필수 복구 및 미저장 초안 확인 유지 |
| 색상과 크기 | indigo 강조, 중립 배경, 터치 가능한 도구와 한국어 안내 |

원본 문서의 셀 크기·내용·100% 확대는 시각 예시와 달라도 보존합니다.
DOCX에 저장된 제목 서식과 문단 경계의 명시적 페이지 나눔을 표시합니다. 내용의 길이로 페이지를 나누지 않습니다.
UI 확인은 실제 Office의 페이지 배치 또는 호스트별 MCP App 검증을 대체하지 않습니다.


## 문서 중심 작업 흐름

공통 상단에는 파일명과 저장 상태, 활동 진입점을 표시합니다. 활동은 필요할 때
열고 리비전은 활동 상세에서 봅니다. DOCX에는 변경이 있을 때 저장 버튼을
표시하며 지원 범위는 본문 아래에서 확인할 수 있습니다. 일반 문단의 텍스트
입력은 한 줄 폭을 채우고, 문단 맨 앞·뒤에서 위·아래 화살표로 다음 입력에
이동할 수 있습니다. 서로 다른 원본 서식 조각은 기존 위치에서 개별 편집합니다.

DOCX에서 브라우저가 동일 세션의 연속 리비전과 AI 저장 이벤트를 함께 확인하면
해당 문단이나 표 셀 옆에 AI 표시를 붙입니다. 이전·이후 미리보기는 각각 최대
280자이며, 현재 브라우저의 제한된 활동 목록에만 보관합니다. 연속 버전을
확인할 수 없거나 미저장 입력 때문에 동기화를 보류한 경우에는 위치나 변경
전후를 추정하지 않습니다. 활동에서 이동하면 문서에서 변경 내용을 펼칩니다.

XLSX는 수식 입력줄, 셀 주소, 시트 탭을 항상 표시합니다. 호환성 안내는 상단
버튼에서 열 수 있고, 활동의 셀 범위는 기록 당시 주소로 이동합니다. 이동 후
서식 도구는 현재 선택한 셀 범위에 적용됩니다.


## 포인터와 모션

XLSX 글꼴·크기 입력에 포커스가 오면 입력칸과 화살표를 하나의 테두리로 표시합니다.
입력에서 Alt+↓로 선택 메뉴를 열고 Escape로 입력에 돌아옵니다. 좁은 화면에서
접힌 도구는 서식 도구 더보기에서 엽니다.
문서 보기 배율과 편집 범위 메뉴도 마우스와 키보드 조작에 맞는 피드백을 표시합니다.
앱 버튼은 같은 호버·누름 피드백과 키보드 포커스를 사용합니다. 클릭 가능한 도구,
사용할 수 없는 도구, DOCX 텍스트 입력은 각각 동작에 맞는 커서를 표시합니다.
XLSX 셀 선택과 크기 조절 커서는 엔진이 관리합니다.

활동 영역에서 Escape를 누르면 닫히고 진입 버튼으로 포커스가 돌아갑니다.
모션 감소 설정에서는 호버·활동 전환과 AI 범위의 움직이는 점선을 줄입니다.
AI가 유휴 상태로 바뀌거나 강조가 만료되면 범위와 상태 문구를 지웁니다.


DOCX 입력 포커스는 본문 아래선과 표 셀의 안쪽 경계로 구분합니다. 공통 활동은
상단의 작은 빈 상태와 변경 타임라인을 사용합니다. 활동을 닫거나 위치로 이동할
때 기존 키보드 포커스와 좁은 화면의 전환 동작을 유지합니다.
