# DOCX 생성과 텍스트 편집

상태: 비공개 로컬 실험 기능. 새 문서 생성, 본문 일반 run과 단순 표 cell의 text
run 교체를 제공합니다. Word 전체 편집기나 정확한 페이지 미리보기가 아닙니다.
Microsoft Word와 LibreOffice native reopen 및 시각 증거는 아직 없습니다.
실제 문서는 복사본으로 작업하세요.

## 새 DOCX 문서

열 파일이 없다면 `foloom -workspace`를 실행하고 터미널에 나온
브라우저 링크를 엽니다.

작업 공간에서 **새 DOCX 문서**를 선택하고 파일 이름을 입력합니다. 이름에
확장자가 없으면 `.docx`를 붙입니다. 경로, 예약 이름, 열려 있는 문서와
중복되는 이름은 사용할 수 없습니다.

새 문서는 저장 위치를 아직 지정하지 않은 작업 복사본입니다. 편집기에서
저장하면 그 복사본에 반영됩니다. 기기에 보관하려면 닫기 전에 DOCX를
다운로드하세요. 작업 탭을 닫으면 임시 복사본이 삭제됩니다.

### 다른 이름으로 복사

DOCX 탭을 선택하고 **다른 이름으로 복사**를 누르면 현재 확정 저장된 버전을
새 작업 탭으로 엽니다. 원본 탭의 미저장 초안은 그대로 남습니다. 초안까지
포함하려면 저장 위치를 확인한 뒤 먼저 명시적으로 저장하세요. 복사본에서
내려받으면 새 이름이 제안되고 실제 저장 위치와 이름은 브라우저가 결정합니다.
브라우저가 직접 파일 쓰기 권한을 제공하지 않아도 다운로드로 보관할 수
있습니다. 복사 요청 중 원본 리비전이 바뀌거나 외부에서 파일이 교체되면
요청을 거절합니다.

### 미저장 초안의 다른 이름 저장

편집기의 **다른 이름 저장**은 현재 초안까지 별도 DOCX로 내보냅니다. 원본
파일, 원본 탭의 미저장 상태와 실행 취소 이력은 유지합니다. 파일 쓰기 권한을
지원하는 브라우저에서는 클릭할 때마다 저장 대상을 명시적으로 선택하며,
선택이 취소되면 파일을 내보내지 않습니다. 대상 쓰기를 완료한 뒤에만 복사본의
기록 완료를 알립니다. 대상 권한이나 디스크 오류는 실패로 표시합니다.

해당 권한을 제공하지 않는 브라우저는 이름에 복사본 표시를 넣은 DOCX의
다운로드를 요청합니다. 이 알림은 기기에 실제 저장이 끝났다는 의미가 아닙니다.
브라우저가 제안한 위치와 파일 이름을 확인하세요. 저장소가 끊기거나 원본이
외부 교체되어도 메모리의 기준 리비전과 초안이 유효하면 이 동작으로 별도
사본을 만들 수 있습니다. 다른 편집으로 기준 리비전 자체가 바뀌면 자동으로
대상을 다시 지정하지 않고 거절합니다.

### 복구 보관

DOCX 편집기의 **복구 보관**에서 이 문서의 보관을 켜면 확정 내용과 유효한
미저장 편집을 이 컴퓨터에 보관합니다. 기본값은 꺼짐입니다. 입력이 잠시
멈추면 보관하고, 저장 직전에도 최신 초안을 보관합니다. 편집기에서 마지막
보관 시각을 확인하세요. 보관은 원본 파일의 저장 성공을 의미하지 않습니다.

서버를 다시 실행한 뒤 작업 공간의 **복구 사본**에서 이름과 보관 시각,
초안 포함 여부를 확인하고 **별도 복사본으로 열기**를 선택하세요. 해당
시점의 편집 내용이 반영된 새 DOCX가 열립니다. 원본 파일과 기존 탭에는
복구 내용이 자동으로 적용되지 않습니다. 필요 없는 보관본은 목록이나 해당
편집기에서 삭제할 수 있습니다. 최대 3개까지 보관하고 마지막 보관 후 7일이
지나면 다음 보관소 접근 시 정리합니다.

연결이 끊겼거나 편집이 검증을 통과하지 못하면 최근 입력이 아직 보관되지
않았을 수 있습니다. 마지막 확인 시각을 보고 탭을 유지하거나 필요한 내용을
먼저 복사하세요. 복구는 확인된 사본을 제공하며, 연결이 끊긴 동안 새로 입력한
내용이나 보관 확인 직전 강제 종료까지 보장하지 않습니다. 서버가 종료된 뒤
남은 작업용 임시 디렉터리는 OS의 임시 파일 정리 정책을 따릅니다.

## 시작

최신 소스에서 `make build`로 바이너리를 만든 뒤 실행합니다. 기존에 설치한 MCP
바이너리는 이 소스 변경만으로 갱신되지 않습니다. 설치 workflow를 사용하는 경우
새 실행 파일로 `mcp install`을 수행한 뒤 호스트를 완전히 다시 시작합니다.
설치된 `foloom` 스킬에 DOCX 절대 경로와 작업을 전달할 수 있습니다.

```sh
./bin/foloom -check /absolute/path/to/document.docx
./bin/foloom /absolute/path/to/document.docx
```

출력되는 인증 URL로 DOCX 브라우저 편집기를 엽니다. 지원 일반 문단은 하나의
본문 편집 영역에서 run 서식을 유지해 표시하며, 보호된 문단의 지원 텍스트는
별도 입력칸으로 편집합니다. 여러 본문·표 입력과 구조를 바꾼 뒤 문서 헤더의
**저장**을 누르면 하나의 리비전으로 저장합니다. Ctrl+S 또는 Command+S도 같은 저장을 수행합니다. 단일 섹션은
원본 용지 크기와 여백을 사용하고, 문단 정렬·앞뒤 간격·글꼴·크기·색상·굵게·
기울임을 기본값, 문단·글자 스타일과 직접 지정 서식에서 읽습니다. 글꼴을 설치하지 않은 환경에서는 대체 글꼴을
사용합니다. 작은 화면에서는 용지와 여백 비율을 줄이고 본문 글자는 읽을 수
있는 크기로 유지합니다.

도구 모음에는 현재 입력의 글꼴과 크기가 표시됩니다. 보기 배율은 브라우저
표시에만 적용합니다.

일반 빈 문단과 비어 있는 run에도 입력칸을 표시합니다. 빈 문단에는
**여기에 입력하세요** 안내가 나타나며 클릭해서 글을 쓸 수 있습니다. 속성만 있는
빈 문단은 문단 속성을 보존하면서 일반 run을 삽입하고 빈 run에는 text만 삽입합니다.
필드·변경 추적 등 보호된 구조에는 빈 입력칸을 추가하지 않습니다. 지원 문단에서 Enter는 실제 DOCX 문단을 나누고 Shift+Enter는 문단 안 줄바꿈을
추가합니다. 문단의 첫 입력 시작에서 Backspace, 마지막 입력 끝에서 Delete는
같은 본문 구간 또는 같은 셀의 인접 문단을 합칩니다. Alt+Shift+↑/↓는 문단을
이동합니다. 여러 줄의 일반 텍스트를 붙이면 여러 문단 초안으로 나눕니다.

구조 변경도 저장 전에는 초안이며 계속 입력·분리·병합한 뒤 한 번에 저장합니다.
서버 실패·충돌에서는 초안을 남기고 자동으로 재시도하지 않습니다. 구조 변경 중
이전 위치 기반 AI 표시는 숨기며 저장 뒤 새로운 revision-scoped ID를 사용합니다.

필드·주석·북마크·변경 추적·구역 속성·명시적 페이지 경계·opaque XML이 있는
문단은 구조 편집을 보호합니다. 지원 텍스트는 기존처럼 편집할 수 있습니다.
병합·중첩 표는 읽기 전용입니다. 지원 일반 문단의 run·문단·표 셀 사이에서
native 선택과 범위 교체를 제공합니다. 같은 본문 구간 안의 선택은 문단을 합칠 수
있지만 다른 셀의 선택을 바꿀 때에는 셀 경계를 유지하고 각 셀 안의 선택 텍스트만
바꿉니다. 보호된 문단이 끼어 있으면 범위 변경을 차단합니다. 선택 밖 run 서식은
유지하고 삽입 텍스트는 선택 시작 run의 서식을 사용합니다.
새 문단은 첫 원본 문단의 문단 서식, 각 run은 참조한 원본 run 서식을 사용합니다.
병합 결과의 문단 서식은 앞 문단을 따릅니다. 지원하지 않는 제어 문자는
계속 거부합니다. native IME·Word 재편집과 모든 문서 호환성을 보장하지 않습니다.

작업 공간의 **내 컴퓨터에서 열기**로 선택한 파일은 원본을 유지하는 작업 복사본입니다.
**저장**은 이 복사본에 반영하며 **다운로드**는 초안을 저장한 뒤 수정본을 받습니다.
**경로로 열기**로 연 문서는 그 경로에 저장합니다.

`페이지·구역 나눔`에서 `문단 끝 페이지 나눔 해제`를 고릅니다. 목록에서
대상 문단을 선택하고 적용한 뒤 저장하면 문단 끝의 명시적 나눔을 제거합니다. HTTP와 MCP에서는
현재 문단 ID로 `update_boundary`의 `no_page_after`를 사용합니다.
문단 안쪽의 나눔과 구역 속성은 유지합니다.

본문은 문단 앞 또는 끝에 저장된 명시적 나눔에서 새 용지로 이어집니다. 자동
페이지 매김, 문단 중간 나눔, 섹션별 배치, 그림, 머리글·바닥글과 복잡한 표 배치는
표시 범위에서 제외합니다. 표는 좁은 화면에서
가로 스크롤합니다. 표시용 메타데이터는 저장 입력에 포함되지 않습니다.

연결 중단이나 외부 변경 및 리비전 충돌 시 미저장 입력을 유지하고 저장을
차단합니다. 필요한 입력을 복사한 뒤 **다시 불러오기**를 누릅니다. 미저장 입력이 있으면 자체
확인 UI의 **입력 버리고 불러오기**를 선택해야 복구합니다. **취소**는 초안을
유지합니다. 저장 결과를 받지 못한 요청은 자동 재시도하지 않습니다. 서버 재시작 뒤에는
새 인증 링크에서 같은 원본 경로를 다시 열어 [확정된 DOCX 이력](#확정된-docx-이력)을
복구할 수 있습니다. 기존 탭의 미저장 텍스트가 필요하면 탭을 새로고침하기 전에
복사하세요. 실행 취소는 같은 탭의 미저장 변경을 먼저 되돌린 뒤 확정 이력을 사용합니다.
다시 실행도 현재 초안과 확정 이력에 맞춰 동작합니다.

## MCP 작업

파일 없이 시작한 stdio와 인증된 HTTP MCP 모두 다음 도구를 제공합니다. 기존
XLSX 도구와 계약은 유지하며 DOCX 활성 문서는 별도로 관리합니다.

| 도구 | 입력과 결과 |
| --- | --- |
| `create_docx` | 새 절대 `.docx` 경로, 순서 있는 paragraph/table block. 생성한 문서를 활성화하고 snapshot과 `browserUrl` 반환 |
| `open_docx` | 기존 절대 `.docx` 경로. 검사 후 활성화하고 snapshot과 `browserUrl` 반환 |
| `get_docx` | 세션 ID, 리비전, 본문·표, run ID, 편집 가능 여부, 호환성 안내 반환 |
| `apply_docx_operations` | 현재 `sessionId`, `baseRevision`, typed operation batch. 원자적 저장 뒤 snapshot 반환 |
| `restore_docx_history` | 현재 `sessionId`, `baseRevision`, `direction: undo 또는 redo`. 확정 batch 한 개를 복원한 뒤 새 revision과 snapshot 반환 |

생성 예시:

```json
{
  "path": "/absolute/path/to/new.docx",
  "blocks": [
    { "type": "paragraph", "text": "회의록" },
    { "type": "paragraph", "text": "결정 사항을 기록합니다." },
    { "type": "table", "rows": [["항목", "담당"], ["초안", "팀"]] }
  ]
}
```

편집 예시의 식별자는 직전 `get_docx`에서 얻은 실제 값으로 바꿉니다.

```json
{
  "sessionId": "current-session-id",
  "baseRevision": 1,
  "operations": [
    {
      "type": "replace_run_text",
      "targetId": "current-body-run-id",
      "expectedText": "회의록",
      "text": "11월 회의록"
    },
    {
      "type": "replace_cell_text",
      "targetId": "current-table-run-id",
      "expectedText": "초안",
      "text": "검토 완료"
    }
  ]
}
```

ID는 세션과 리비전에 묶여 있습니다. 성공한 저장 뒤에는 최신 snapshot의 ID를
사용합니다. 반복되는 같은 문자열도 ID로 구분하며 문자열 검색으로 위치를 추측하지
않습니다. `expectedText` 불일치, 잘못된 ID, 중복 대상, 오래된 리비전, 미지원
operation이 하나라도 있으면 전체 batch를 거부합니다. 내용이 같은 batch는 파일과
리비전을 바꾸지 않습니다. `browserUrl`은 2분 동안 한 번만 사용할 수 있습니다.

## 지원과 보존 범위

- 생성: 문단, 직사각형 단순 표, 한글·Latin text, 공백과 XML 특수 문자
- 편집: 본문의 일반 text run, 병합되지 않은 단순 표의 일반 text run
- 보존: 대상 text element 이외 XML byte와 다른 ZIP part의 압축 해제 payload
- 읽기 전용 또는 생략: 변경 추적, field, hyperlink, content control, 병합·중첩 표,
  그림, 머리글·바닥글, note, comment와 알 수 없는 구조
- 미지원: run을 가로지르는 교체, 문단·행·열 추가 및 삭제, 새 서식 적용, 표 구조
  편집, 탭·줄바꿈 입력, 정확한 pagination, PDF 변환, DOC·DOCM·암호화·서명 문서,
  strict OOXML과 비표준 main document mapping

원본 run의 서식과 주변 구조는 다시 만들지 않습니다. text element에는 필요한 경우
`xml:space="preserve"`를 추가합니다. 기존 `xml:space="default"` 대상에 양끝 공백을
새로 넣는 작업은 거부합니다. ZIP 압축 byte와 timestamp까지 동일하다는 계약은
아닙니다. 전체 Word 호환성이나 모든 문서의 무손실 편집을 주장하지 않습니다.

## 안전 저장과 제한

기존 파일은 symlink를 해석해 연 뒤 regular file인지 확인합니다. 저장 시 협조
writer lock과 원본 hash를 확인하고, 같은 디렉터리의 임시 파일을 sync·close한 뒤
원자적 replacement를 수행합니다. 최종 교체 직전에도 원본을 검사합니다. Word
등 비협조 writer와 마지막 검사·교체 사이의 race는 남으므로 외부 앱과 동시 저장을
피하세요. 프로세스 중단으로 남은 `.document-workspace.lock`은 자동으로 훔치지
않으며 writer 종료를 확인한 뒤 관리자가 처리해야 합니다.

생성은 완성된 임시 파일을 exclusive hard link로 설치하므로 기존 파일이나 symlink를
덮어쓰지 않습니다. hard link를 제공하지 않는 파일 시스템에서는 생성에 실패합니다.
리비전은 현재 프로세스 세션 안에서 유효하며 다시 열면 새로운 세션 ID로 시작합니다.
영속 이력과 디렉터리 fsync에 의한 전원 장애 복구 보장은 제공하지 않습니다.

| 제한 | 값 |
| --- | --- |
| 압축 파일 / 전체 확장 / part | 32 MiB / 64 MiB / 16 MiB |
| ZIP entry / XML 깊이 / XML node | 2,048 / 64 / part당 100,000 |
| XML token | part당 500,000, 잘게 분할된 text는 누적 buffer로 처리 |
| 검사 식별자 수 | 10,000 |
| batch operation / 교체 text 합계 | 1,000 / 4 MiB |
| run text | UTF-8 64 KiB, 탭·줄바꿈과 XML 비허용 문자 거부 |
| 생성 block / 총 문단·cell | 1,000 / 3,000 |
| 생성 표 | 100행, 50열 이하 |
| 브라우저 쓰기 body | 1 MiB |
| event replay | 최근 commit 128개 |

외부 relationship은 보존만 하고 네트워크로 가져오지 않습니다. archive traversal,
중복 entry, 잘못된 내부 relationship, XML directive, 과도한 구조, macro와 서명은
거부합니다. 브라우저는 문서 text를 HTML로 해석하지 않으며 기존 token, cookie,
Origin과 CSP 경계를 사용합니다.

## 문단 구조 도구 계약

`apply_docx_operations`와 `/api/docx/operations`의 `replace_paragraphs`는 같은
부모의 연속된 `structureEditable` 문단 범위를 받습니다. `targetId`와
`endTargetId`는 처음과 마지막 문단 ID, `expectedText`는 원본 문단 텍스트를 LF로
이어 붙인 값입니다. `text`는 빈 문자열입니다. `paragraphs`의 각 항목은 문단
서식용 `sourceId`와 `runs`를 가지며 각 run도 범위 안 원본 run의 `sourceId`와
새 `text`를 가집니다. source ID는 현재 리비전의 참조이며 새 OOXML ID가 아닙니다.
문단 배열을 늘리거나 줄이고 순서를 바꿔 추가·분리·병합·삭제·이동합니다.
결과는 최소 한 문단이며 한 계획은 최대 1,000문단입니다. 쓰기 범위끼리 겹치면
하나의 계획으로 합쳐야 합니다.

같은 문단을 여러 번 참조해도 원본 고유 ID를 복제하지 않습니다. 원본 run의 서식과
필요한 XML namespace를 함께 옮기며 계획 범위 밖 document XML과 다른 package
part는 유지합니다. 수정된 문단 안 XML의 byte 동일성은 보장하지 않습니다.
`replace_run_text`와 `replace_cell_text`의 LF는 `w:br`이며 새 문단이 아닙니다.

## 연속 선택과 문자 경계

본문의 방향키·Home/End·단어 이동과 드래그 선택은 브라우저의 native 선택을
사용합니다. 범위 쓰기 전에 선택을 문단/run의 UTF-16 위치로 변환하고 grapheme
경계를 검사합니다. 이모지 ZWJ, skin tone과 조합 문자를 중간에서 자르지 않습니다.
지원하지 않는 Intl 환경에서는 문자 경계를 추정해 분할하지 않습니다.

일반 run 안의 연속 타이핑은 입력 DOM을 유지하고 문단 경계를 바꾸는 작업만
초안 계획으로 반영합니다. native IME가 DOM을 소유하는 동안 다시 렌더링하지
않고 compositionend의 최종 텍스트를 한 번 적용합니다. 조합 중에는 저장을
차단하며 실제 OS·기기 IME 인증은 실행한 환경만 별도로 기록합니다. 검색은
미저장 본문의 run 텍스트도 읽고 저장은 확정된 응답 뒤에만 완료 상태를 표시합니다.

## Clipboard와 기본 글자 서식

도구 모음의 **붙여넣기 서식**에서 기본값 **텍스트만** 또는 **기본 서식 유지**를
고릅니다. Ctrl/Cmd+Shift+V는 텍스트만 사용합니다. 기본 서식은 굵게·기울임,
120 UTF-8 byte 이하 글꼴 이름, 4~144pt 크기와 불투명 RGB 색으로 제한합니다.
문단·표·그림·링크·목록·고급 서식의 완전한 clipboard 이식은 아닙니다.
지원하지 않는 항목은 안내하고 텍스트와 지원 글자 서식만 사용합니다. 이미지 alt는
텍스트로 보존할 수 있지만 외부 그림을 내려받거나 임베디드 코드를 실행하지 않습니다.
보호된 구조의 별도 입력칸에서는 기존 일반 텍스트 붙여넣기를 사용합니다.

HTML은 live DOM에 붙이지 않고 inert template에서 제한된 텍스트·서식 값만 읽습니다.
문서가 있는 부모의 source run을 참조하고 새 run에 명시적 `style`을 추가합니다.
서버가 색·글꼴·크기와 전체 계획을 다시 검증하고 지정하지 않은 원본 run 속성을
유지합니다. 잘라내기는 clipboard 기록이 성공한 다음 초안에서 범위를 삭제합니다.
텍스트 없는 이미지 clipboard는 선택을 삭제하지 않습니다. 탭과 제어 문자, 요청
크기 등 저장 제한은 유지하며 지원하지 못한 입력을 성공으로 표시하지 않습니다.

### 입력기 조합과 저장 요청

조합 중에는 브라우저가 본문 DOM을 소유합니다. Enter를 문단 분리로
해석하거나 중간 글자를 저장하지 않습니다. 도구 또는 작업 공간에서 온 저장
요청은 조합 완료까지 기다리며 같은 조합의 요청을 한 번의 batch로 묶습니다.
최종 조합이 끝난 뒤 검증과 저장이 성공해야 저장 완료로 응답합니다.

조합 취소는 원래 텍스트와 선택 방향을 복원합니다. 조합 중 원격 확정이
발생하면 초안을 보존하고 충돌 상태로 전환하며 대기 중 저장은 실패로
응답합니다. 연결 실패와 문서 종료도 대기 요청을 해제합니다. 사용자가
입력을 복사하고 명시적으로 다시 불러오기 전에는 자동 재시도하지 않습니다.
OS의 실제 한국어·일본어·중국어 입력기 검증은 DOM composition 회귀와
구분하며 실행하지 않은 조합은 검증 완료로 간주하지 않습니다.

### 확정된 DOCX 이력

`get_docx`와 HTTP snapshot의 `history`는 undo·redo 개수와 다음 복원 대상
batch의 actor(`human` 또는 `ai`)를 반환합니다. 사람·AI의 확정 batch는 하나의
시간순 이력에 쌓입니다. 실행 취소는 다음 actor를 확인한 뒤 현재 `sessionId`,
`baseRevision`, `direction: undo`로 `restore_docx_history` 또는
`POST /api/docx/history`를 호출합니다. 다시 실행은 `direction: redo`입니다.
복원 자체도 새 revision과 ordered event를 발행하며 과거 revision으로
되돌아가지 않습니다. 빈 이력·잘못된 방향·다른 세션·stale revision은 거부합니다.

이력은 개별 XML 역연산이 아닌 전체 DOCX snapshot입니다. 지원 batch의 문단·
글자 서식 외에 표·그림·미지원 part도 해당 확정 시점의 바이트로 복원합니다.
새 편집을 확정하면 redo 분기를 폐기합니다. undo와 redo를 합해 최대 10개,
64 MiB의 과거 snapshot을 유지하며 초과 시 오래된 undo부터 줄입니다.
현재 문서와 임시 저장 공간은 이 보관 한도와 별개입니다.

정규화한 원본 경로별 `.document-workspace-docx-history/<경로 SHA-256>`에
비공개 snapshot과 manifest를 저장합니다. 이 디렉터리에는 문서 내용이
포함되므로 Git에서 제외합니다. 작업 복사본은 해당 복사본 디렉터리 안에 이력을
두며 파일 닫기 시 함께 정리됩니다. 원본 경로의 이력은 재시작 후에도 남습니다.
파일을 이동하면 별도 이력으로 시작합니다. 원본 파일만 복사해서는 이력이
이동하지 않습니다.

파일 writer lock 안에서 현재 hash를 확인하고 이전 snapshot과 다음 manifest를
먼저 준비합니다. DOCX를 같은 디렉터리의 임시 파일로 원자 교체한 다음
manifest를 확정합니다. 교체 전 실패는 원본과 revision을 유지합니다. 교체 후
manifest 확정만 실패하면 문서는 확정된 것으로 응답하고 경고를 표시합니다.
재시작은 pending의 현재 hash가 실제 DOCX와 같을 때만 확정 이력을 복구합니다.
다른 hash의 pending은 폐기하며 손상·누락된 이력은 경고 후 새 이력으로
시작합니다. 잘못된 이력을 문서에 자동 적용하지 않습니다. sidecar 경로와
snapshot은 symlink를 거부하고 크기·hash·manifest 경로를 검증합니다.

이 보장은 프로세스 중단 후 재열기 기준입니다. 파일 시스템·전원 장애로 저장
장치가 동기화된 데이터를 잃는 경우까지 완전한 내구성을 주장하지 않습니다.

### 초안과 확정 이력의 UI 경계

실행 취소·다시 실행 버튼과 Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl+Y는 같은
controller 이력을 사용합니다. 브라우저의 contenteditable 자체 undo와 서버
undo를 동시에 실행하지 않습니다. 검색창과 본문 밖 입력창의 undo는 해당
입력창에 남겨 둡니다. 조합 중과 저장·불러오기·충돌·연결 실패 상태에서는
문서 이력 복원을 실행하지 않습니다. 보호된 run의 textarea도 저장 대기를
controller에 알리며 조합 최종값 확정 전에는 저장하지 않습니다.

동일 run의 750 ms 이내 연속 타이핑은 한 초안 단계입니다. 문단 분리·병합·
범위 교체·붙여넣기는 각각 한 단계입니다. 초안 이력은 메모리에 최대 10개,
문자열 추정 32 MiB로 제한합니다. 새 입력은 초안 redo를 폐기합니다. 초안을
모두 취소한 뒤에만 서버의 확정 작업을 취소할 수 있습니다. 저장 성공과 명시적
다시 불러오기는 초안 이력을 비웁니다. 저장 실패는 초안과 이력을 보존하지만
연결 복구를 확인하기 전에는 다시 쓰지 않습니다. 초안 이력이 있는 상태에서
서버 복원을 실행하면 해당 초안 redo는 새 확정 경계에서 비워집니다.

버튼 설명은 다음 작업이 미저장 초안인지 사람·AI의 확정 batch인지 표시합니다.
전체 batch 이력을 복원하므로 AI 작업도 사용자 작업과 같은 순서로 취소됩니다.
복원 전후에 같은 고유 문단 ID가 있으면 해당 문단 안에서 선택 방향과 위치를
복원합니다. 해당 문단이 삭제되면 선택을 해제합니다. 고유 문단 ID가 없는
선택은 run 순서와 유효한 offset으로 복원합니다.

### 선택 글자 서식

글자 서식 도구는 현재 본문 선택 또는 커서 위치에 적용됩니다. 글꼴·크기·
굵게·기울임·밑줄·취소선·색·강조·위/아래 첨자와 직접 서식 지우기를 지원합니다.
굵게·기울임·밑줄은 Ctrl/Cmd+B·I·U도 사용합니다. 선택은 도구로 focus를 옮겨도
유지되며, 적용 후 편집 본문에서 같은 방향의 범위를 복원합니다. 혼합 선택은
속성별 혼합 상태로 표시합니다. 미선택 속성은 바꾸지 않습니다.

선택이 접혀 있으면 빈 서식 run을 만들고 이후 입력을 그 위치에 이어 붙입니다.
문단 분리는 해당 run 서식을 이어받습니다. 병합은 원래 run별 서식을 유지합니다.
서식 적용·취소와 원본 형식 저장은 같은 문단 source plan과 batch 이력을 사용합니다.
각 동작은 저장 전 초안이며 저장 성공 전에는 원본 저장 완료로 표시하지 않습니다.

글자 범위에 걸친 run은 선택 시작·끝에서만 분리합니다. 선택 밖 rPr와 알려지지
않은 속성은 그대로 사용합니다. 굵게만 바꿀 때 테마·Latin·동아시아 글꼴·언어를
재지정하지 않습니다. 글꼴을 명시적으로 선택하면 해당 범위의 ascii·hAnsi·
eastAsia·cs 글꼴을 같은 이름으로 지정합니다. 설치되지 않은 글꼴은 브라우저와
Word가 서로 다른 대체 글꼴로 표시할 수 있습니다. 브라우저가 선택한 글꼴을
로컬 이름으로 확인하지 못하면 글꼴 도구에 대체 글꼴 가능성을 표시하며
설치 여부나 native 조판 일치를 보장하지 않습니다.

직접 서식 지우기는 지원하는 글자 속성만 제거합니다. 문단·글자 스타일 참조와
언어·알려지지 않은 나머지 속성은 남기며 원본 스타일의 상속값을 미리 봅니다.
문서 전체 스타일을 삭제하거나 모든 OOXML 서식을 정규화하는 동작이 아닙니다.
미리 보기는 단일 밑줄·취소선·일부 강조색·첨자 위치를 표현하며 Word의 정밀
조판이나 복합 밑줄 모양까지 일치한다고 주장하지 않습니다.

### 문단 서식

문단 도구는 커서가 있는 문단 또는 선택이 닿은 문단에 적용합니다. 선택 끝이
다음 문단의 첫 위치이면 그 다음 문단은 포함하지 않습니다. 시작·가운데·끝·
양쪽 정렬, 좌우 들여쓰기, 첫 줄/내어쓰기, 앞뒤 간격, 배수·고정·최소 줄 간격,
읽기 방향과 가로/세로 쓰기를 지원합니다. UI 길이는 pt이며 저장 계약의 길이는
1 pt = 20 twips입니다. 첫 줄 입력이 음수이면 내어쓰기를 사용합니다.
배수 줄 간격은 OOXML의 240분율이며 고정·최소 간격은 twips입니다.

정렬의 시작·끝은 읽기 방향에 따른 논리적 위치입니다. 읽기 방향과 세로 쓰기는
별도 속성입니다. 서로 다른 문단 속성은 혼합으로 표시합니다. 길이·줄 간격은
서버에서도 제한을 검증하며 잘못된 batch는 일부만 저장하지 않습니다.

문단 속성 변경은 source pPr의 해당 속성만 교체합니다. 들여쓰기를 지정하면
같은 방향의 문자 단위·start/end 대체 속성을 제거하고, 첫 줄과 내어쓰기는
서로 배타적으로 저장합니다. 앞뒤 간격을 지정하면 해당 before/afterLines와
자동 간격 속성만 제거합니다. 미지정 탭·테두리·언어·다른 속성은 유지합니다.
알 수 없는 내용을 가진 대상 속성과 중복 대상 속성은 변경하지 않습니다.
변경한 pPr 속성 순서는 Word 스키마 순서로 정리합니다. 구역·필드·앵커 등의
보호된 문단은 이 문단 계획 범위에 새로 포함하지 않습니다.

저장 뒤에는 도구가 보관한 선택도 새 리비전의 run ID로 다시 연결합니다.
쓰기 방향·범위·viewport 변화 뒤에는 전체 페이지 대신 선택의 focus 쪽 커서를
스크롤 영역 안으로 드러냅니다. 초점이 다른 입력 도구에 있으면 화면 크기 변경만으로
본문 스크롤을 이동하지 않습니다. 세로 쓰기는 자동 페이지 매김 없이 흐르는
미리 보기이며 native Word의 페이지별 줄바꿈·배치 검증은 별도로 필요합니다.

### 문서 스타일 적용과 정의 편집

문단·글자 스타일 선택은 현재 선택 범위에 참조를 적용합니다. 스타일 이름을
같게 만들어도 별도 ID로 구분하며 목록에 ID를 함께 표시합니다. 문단 스타일
제거는 기본 문단 상속으로 돌아가고 글자 스타일 제거는 해당 rStyle 참조만
제거합니다. 직접 글자·문단 속성은 남아 스타일보다 우선합니다. 직접 서식
지우기는 지원 글자 속성을 제거하므로 스타일의 값이 드러납니다.

`스타일 정의 편집`에서 새 문단/글자 스타일을 추가하거나 이름·기준 스타일·
글자·문단 속성을 수정합니다. 정의 변경과 본문 참조는 미저장 초안이며 한 번의
저장에 함께 넣을 수 있습니다. 정의 초안은 작업 공간의 미저장 경고와
실행 취소·다시 실행에도 포함됩니다. 스타일 정의나 참조를 바꾼 뒤의 본문
스타일 미리 보기는 저장 후 서버에서 상속과 직접 서식 우선순위를 다시 계산해
갱신합니다. 저장 전에는 기존 본문 모양을 유지하며 그 제한을 도구에 표시합니다.

정의 도구에서 비어 있는 속성은 기준 스타일을 따릅니다. 굵게·기울임·취소선의
스타일 속성은 Word의 토글 규칙으로 상속 상태를 반전합니다. false 또는 속성
제거는 반전을 하지 않습니다. 같은 이름의 직접 run 속성은 절대적인 켜기/끄기
값입니다. 문단 스타일의 run 상속 뒤 글자 스타일 체인을 적용하고 마지막에
직접 run 속성을 적용합니다. 상속 길이는 32단계까지이며 순환·없는 기준·종류가
다른 기준 스타일을 거부합니다. UI가 만든 순환 초안은 서버에 보내기 전에
고칠 수 있습니다. 서버도 전체 batch를 다시 검증합니다.

MCP와 HTTP는 `apply_docx_operations`의 `define_style` operation을 사용합니다.
`styleDefinition`은 `id`, `kind: paragraph|character`, 새 정의의 `name`, 선택적
`basedOn`, `run`, `paragraph`를 받습니다. 기존 정의의 생략한 속성은 유지하며
빈 `basedOn`은 상속을 제거합니다. 한 batch는 최대 32개 정의를 변경합니다.
`paragraphs[].format.styleId`와 `paragraphs[].runs[].style.styleId`는 기존 또는
같은 batch에 정의한 스타일을 참조하며 빈 문자열은 참조를 제거합니다.

스타일 part가 있으면 원래 관계가 가리키는 경로를 수정하고 다른 part와
스타일 메타데이터를 보존합니다. 스타일 part가 없으면 충돌하지 않는 새 파일과
관계·content type을 추가합니다. 이름 공간 prefix와 ZIP header를 보존하며
새 속성은 스키마 순서에 넣습니다. 보호된 변경 추적·알려지지 않은 구조가 있는
정의는 UI에서 수정하지 않고 새 정의를 만들 수 있습니다. 스타일 목록은 최대
500개를 표시하며 나머지 정의도 원본에 남습니다. 목록에서 생략한 정의는
현재 UI에서 편집할 수 없습니다. native Word의 전체 스타일 시각 호환성은
별도 검증이 필요합니다.

`다른 이름 저장`은 이름을 제안하는 다운로드를 요청합니다. `저장 위치 선택`은 지원 브라우저에서만 파일 선택창을 열고, 미지원 환경에서는 다운로드를 요청합니다.

### 표의 행·열 구조

`update_table`은 현재 리비전의 `targetId`와 `table.action`을 받습니다.
`insert`는 편집 가능한 본문 문단 뒤에 `rows`와 `columns`만큼 빈 표를
만듭니다. `delete`는 편집 가능한 표를 삭제합니다. `add_row`, `delete_row`,
`move_row`와 대응하는 `*_column`은 표 ID 및 0부터 시작하는 `index`를
받습니다. 이동의 `destination`은 이동 후 위치입니다.

최대 100행, 50열, 3,000셀의 사각 표를 편집합니다. 기존 열과 셀 XML은
함께 이동하고, 바뀌지 않은 행·셀 및 서식은 그대로 보존합니다. 병합·중첩,
불규칙한 열, 개정 마크와 주석·북마크 범위가 있는 표는 구조 변경을 거절합니다.
같은 표의 구조 변경과 겹치는 텍스트 변경은 별도 저장으로 나눕니다.

단순 표의 `행 높이 설정`에서 행 번호와 최소 높이(1~1,584 pt)를 정하고 저장합니다.
Word의 최소 높이(`atLeast`)로 기록되므로 셀 내용에 따라 행이 더 커질 수 있습니다.
기존 머리행과 다른 행 속성·셀 내용은 보존합니다.
[Word 행 높이 범위](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/5919e0bd-e6ce-477e-8d66-0e5282f5c506)를 따릅니다.

브라우저에서 `표 편집`을 열어 작업을 선택합니다. 새 표는 커서를 둔 본문
문단 뒤에 삽입하며 문단을 선택하지 않으면 편집 가능한 마지막 문단을 사용합니다.
행·열 위치는 화면에서 1부터 시작합니다. 한 번에 표 작업 하나를 적용하고
저장합니다. 저장 전에는 실행 취소로 초안을 취소할 수 있으며 저장 후에는
확정 이력에서 표 작업을 되돌릴 수 있습니다.

단순 표에서 커서가 한 곳에 있을 때 Tab과 Shift+Tab은 다음 또는 이전 편집
가능한 셀로 이동합니다. 표의 양 끝에서는 기본 키보드 탐색으로 돌아갑니다.
새 행은 표 도구에서 추가합니다.


## 목록 작성

본문이나 단순 표의 문단을 선택해 새 글머리·번호 목록을 만듭니다. 새 목록은
기존 목록과 분리된 번호 인스턴스를 사용합니다. 시작 번호를 지정해 다시
시작하거나, 저장된 목록을 선택해 이어 쓸 수 있습니다. 선택한 문단의 수준은
도구 모음과 Tab/Shift+Tab으로 바꿉니다. 목록이 아닌 문단의 Tab은 브라우저의
초점 이동을 유지합니다.

Enter는 같은 목록의 다음 항목을 만들고, 빈 목록 항목에서 Enter를 누르면
그 문단의 목록을 끝냅니다. Shift+Enter는 같은 항목의 줄 나눔입니다.
목록 변경과 문단 내용은 한 batch로 저장하고 한 번에 실행 취소합니다.
직접 번호 참조와 상속 번호 참조를 해제할 때는 numId 0을 명시합니다.

새 목록은 기본 글머리와 decimal 9수준을 지원합니다. 가져온 목록은 원래
numbering part와 사용자 정의 글머리를 보존합니다. 일부 고급 번호 형식과
재시작·스타일 연결 규칙은 브라우저 미리보기와 native 비교를 추가 검증 중이며
가져온 목록은 [Word의 단계별 재시작 규칙](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/140a2cd9-2f26-456d-9760-ae6ecef4e8b5)에
따라 지정한 상위 단계에서 다시 시작하거나 번호를 계속 이어갑니다.
[법률식 번호 지정](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.islegalnumberingstyle)이
켜진 목록 단계는 해당 표시 문자열에 포함된 모든 번호를 십진수로 표시합니다.
새 번호 목록을 만들기 전에 `목록 번호 형식`에서 일반 숫자, 대문자·소문자 로마 숫자 또는
대문자·소문자 영문자를 선택할 수 있습니다. `define_list`의 `kind`는 `decimal`,
`upperRoman`, `lowerRoman`, `upperLetter`, `lowerLetter` 또는 `bullet`을 사용합니다.
영문자는 1~702 범위에서 Word의 반복 문자 번호를 표시합니다. Z 다음에는 AA와 BB가 이어집니다. 로마 숫자 목록은
시작 값을 1~3,999 사이로 지정합니다.

로마 숫자 목록은 1~3,999 범위의 대문자·소문자 번호를 표시합니다. 다른 미지원 형식은 형식 이름으로 표시합니다. 기존 공유 번호 정의 자체를
다른 내용으로 덮어쓰는 UI는 제공하지 않습니다.


## 문단 탭 위치와 문자

본문 선택 뒤 `탭 위치·정렬`을 열어 위치(pt), 왼쪽·가운데·오른쪽·소수점·세로선
정렬과 채움선을 적용합니다. `이 위치 해제`는 상속한 위치도 명시적으로 해제하며,
다른 위치의 탭과 사용자 정의 속성은 유지합니다. 첫 선택 문단의 위치 목록을
누르면 편집값을 불러옵니다. 여러 문단을 선택하면 같은 위치의 변경만 적용합니다.
기본 위치 간격은 36pt이며 사용자 지정 위치는 0~1440pt, 한 번에 최대 32개입니다.

`탭 문자 삽입`은 공백 여러 개가 아닌 실제 Word 탭을 넣습니다. 일반 Tab 키는
초점 이동, 목록의 Tab/Shift+Tab은 수준 변경을 유지합니다. 저장할 때는 `w:tab`
요소를 사용하고, 줄 나눔은 `w:br`로 보관합니다. 탭 위치와 내용은 기존 저장·
초안 이력의 같은 batch로 적용됩니다.

화면은 뒤따르는 필드의 실제 브라우저 폭을 사용해 정렬하고 채움선은 장식으로
그립니다. 선택·복사 텍스트에 채움 문자나 가짜 공백을 넣지 않습니다. 기본 탭은
36pt 간격, 소수점은 첫 점 또는 쉼표를 기준으로 미리 봅니다. 긴 줄의 자동 줄바꿈,
RTL·세로 쓰기와 복잡한 글꼴 shaping은 Word와 다를 수 있습니다. 페이지 조판의
정확한 일치는 #93과 native 검증에 남으며 완료로 주장하지 않습니다.

## 구역 설정 계약

snapshot의 `sections`는 최대 128개 구역의 현재 리비전 ID, 본문 block 범위,
용지·여백, 방향, 단 수와 간격, 구역 나누기 유형을 반환합니다. 문단의 `sectPr`는
그 문단에서 끝나는 구역의 속성이고, 본문 마지막 `sectPr`는 마지막 구역입니다.
문단 경계의 페이지 나눔과 구역 나눔은 서로 다른 속성입니다.

`update_section` operation은 `sectionId`와 `section`을 받습니다. 용지 폭·높이는
2000~50000 twip, 방향은 portrait/landscape, 여백은 0 이상이며 내용 영역은
최소 1200 twip입니다. 단 수는 1~12, 간격은 0~14400 twip이고 각 단에 최소
240 twip을 남겨야 합니다. 나누기는 nextPage, continuous, evenPage, oddPage,
nextColumn을 사용합니다. 생략한 속성, 머리글·바닥글 참조, 쪽 번호와 custom
속성은 변경하지 않습니다. 기존 서로 다른 폭의 단과 변경 추적 구역은 보호합니다.

다른 쓰기와 같은 기준 리비전·전체 batch 검증·원자적 저장·확정 이력을 사용합니다.
구역 설정과 같은 XML 범위를 바꾸는 구조 작업은 충돌로 거절합니다. 구역 삽입과
머리글·바닥글 편집, 실제 쪽 수 연결은 #90의 후속 커밋에서 진행하며 아직 완료로
집계하지 않습니다. 정확한 자동 조판은 #93에서 별도 검증합니다.

`구역·용지 설정`에서 편집할 구역을 선택하고 값을 바꾼 뒤 `선택 구역 적용`을
누르면 초안에 반영됩니다. 저장 버튼으로 본문과 같은 리비전에 확정하며 적용
전의 입력값만으로 원본을 변경하지 않습니다. 초안의 실행 취소·다시 실행과
확정 이력을 함께 사용합니다. 화면은 구역별 용지·여백·단을 구분하고, 연속
구역도 경계 확인을 위해 별도 미리보기로 표시합니다. 이 분리 표시를 실제
페이지 나눔이나 실제 쪽 수로 간주하지 않습니다.


### 머리글·바닥글의 구역 계약

`update_section.section.headerFooters`는 최대 여섯 가지 `kind: header|footer`,
`variant: default|first|even` 조합을 받습니다. 새 텍스트는 `text`, 이전 구역
연결은 `linkPrevious: true`를 사용하고 둘을 함께 지정하지 않습니다. 첫 구역은
이전 연결을 지정할 수 없습니다. 빈 텍스트는 명시적인 빈 머리글이며 이전
구역 상속과 구분합니다. 한 batch에서 최대 32개 내용을 변경합니다.

항상 새 part와 relationship을 만들고 대상 구역의 참조만 교체합니다. 원래
part, 다른 구역의 명시적 참조와 다른 variant는 그대로 보존합니다. 연결을
복원하면 그 구역의 참조를 제거하며 원래 part는 삭제하지 않습니다. 같은
batch의 스타일 생성도 content type과 relationship을 함께 유지합니다.

snapshot은 각 variant의 직접·상속 상태, 내용 원본 구역, 단순 텍스트와
편집 가능 여부를 반환합니다. 상속 내용은 원본 구역 ID로 찾아 중복 전송하지
않습니다. 내용 미리보기 총량은 1 MiB이며 한 내용은 64 KiB까지입니다. 한도를
넘으면 `truncated`와 읽기 전용 상태를 반환해 빈 내용으로 오인해 저장하지
않습니다. 서식·필드·그림·추적 변경 등 단순 텍스트가 아닌 기존 내용은 보호합니다.

`firstPage`는 구역의 `titlePg`만 바꾸며 첫 페이지 머리글과 바닥글을 구분합니다.
even variant 작성은 참조를 보관하지만 문서 전체의 홀짝 구분 설정을 새로 켜는
화면과 실제 쪽 선택은 아직 구현 중입니다. 화면 작성 도구는 다음 커밋에서
연결하며 native Word 조판은 미검증입니다.

이전 구역 상속과 첫·홀짝 구분은 [Microsoft Open XML 문서](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.headerreference)를 기준으로 구현합니다.


`머리글·바닥글`에서 구역·종류·페이지 구분을 선택해 단순 텍스트를 작성하고
`내용 적용` 후 저장합니다. `첫 페이지 구분`도 내용 적용 때 함께 초안에
반영됩니다. 연결된 내용을 적용하면 그 구역의 독립된 내용이 되며, `이전
구역 연결`로 다시 상속할 수 있습니다. 미저장 머리글·바닥글도 본문과 같은
실행 취소·다시 실행에 포함합니다. 서로 다른 variant의 초안을 덮어쓰지 않습니다.
미리보기는 구역의 첫 페이지 구분에 맞는 대표 머리글·바닥글을 보여 주며 정확한
쪽 수·페이지별 반복은 아직 검증하지 않습니다. 새 홀짝 구분 활성화는 후속입니다.

보호된 머리글 내용도 `첫 페이지 구분 적용`으로 구분 설정만 바꿀 수 있습니다. 이 동작은 내용이나 참조를 평탄화하지 않습니다.

### 문서 전체의 홀수·짝수 구분

`머리글·바닥글`에서 문서 전체 홀수·짝수 구분을 설정하고, 각 구역의 기본·홀수와
짝수 내용을 따로 편집할 수 있습니다. `update_header_parity`는
`evenAndOddHeaders`에 불리언을 받으며 문서의 settings part에서 해당 속성만
바꿉니다. 다른 머리글 참조와 첫 페이지 구분은 그대로 유지됩니다. 브라우저
미리보기는 같은 구역에 속한 명시적 페이지 그룹을 세며, 정확한 자동 페이지
구성과 홀짝 계산은 #93에서 다룹니다.
[Open XML 홀짝 설정](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.evenandoddheaders)을 따릅니다.

### 구역별 쪽 번호

`구역·용지 설정`에서 번호를 이어가거나 0 이상의 정수에서 다시 시작하고,
숫자·로마 숫자·알파벳 형식을 선택할 수 있습니다. 적용 후 본문과 함께
저장하거나 실행 취소할 수 있습니다.

`update_section`의 `pageNumberStart`는 지정 번호, `-1`은 이전 구역에서
계속을 뜻합니다. 계속은 `w:pgNumType`의 `w:start` 속성만 제거합니다.
`pageNumberFormat`은 `decimal`, `upperRoman`, `lowerRoman`, `upperLetter`,
`lowerLetter` 중 하나입니다. 생략된 속성과 기존 장 번호·구분 문자는
유지합니다. [Open XML 쪽 번호 속성](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.pagenumbertype)을 따릅니다.
머리글·바닥글 도구의 `쪽 번호 필드`를 켜면 내용 뒤에 Word의 PAGE 필드를
추가합니다. HTTP·MCP는 머리글·바닥글 설정에 `pageNumber: true`를 보냅니다.
`false`는 필드를 제거하고, 값 생략은 해당 구역의 기존 독립 필드를 유지합니다.
브라우저에서는 필드 위치를 표시하며 실제 쪽 번호는 Word 등 외부 편집기에서
계산합니다. [단일 Word 필드 구조](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.simplefield)를
사용합니다.

같은 도구의 `전체 쪽 수 필드`를 켜면 Word가 계산하는 NUMPAGES 필드를
추가합니다. HTTP·MCP의 머리글·바닥글 설정은 `totalPages: true` 또는
`totalPages: false`를 사용합니다. 쪽 번호 필드와 독립적으로 바뀌며, 브라우저는
계산값 대신 필드 위치를 보여 줍니다.
[Word 필드 코드 목록](https://support.microsoft.com/en-us/word/list-of-field-codes-in-word)에서 NUMPAGES를 확인할 수 있습니다.

### 문단 페이지 나눔과 구역 나눔

`구역 나눔 제거`에서 경계를 선택하고 저장하면 앞뒤 구역을 합칩니다.
합친 구역은 뒤 구역의 설정을 사용합니다. 본문 글과 관련 패키지 part는 보존합니다.
HTTP·MCP에서는 경계 문단 ID로 `update_boundary`의 `remove_section`을 사용합니다.

기존 구역 나눔을 선택하고 `구역 나눔을 앞 문단으로 이동` 또는
`구역 나눔을 뒤 문단으로 이동`을 적용합니다. HTTP·MCP의 `update_boundary`는
기존 경계 문단 ID와 `move_section_earlier` 또는 `move_section_later`를 받습니다.
구역 설정과 관련 관계는 그대로 사용하고 구역에 속하는 문단만 달라집니다.
빈 구역, 표, 페이지 나눔이나 보호된 문단을 포함하는 이동은 거절합니다.


본문 문단에 커서를 놓고 `페이지·구역 나눔`을 열어 문단 앞 페이지 나눔을
설정·해제하거나 문단 뒤에 다음 페이지 또는 연속 구역 나눔을 삽입합니다.
다른 초안은 먼저 저장하거나 실행 취소합니다. 새 경계는 저장 후 미리보기에
반영되며 실행 취소할 수 있습니다.

`update_boundary`는 현 리비전의 본문 문단 ID와 `boundary` 값
`page_before`, `no_page_before`, `section_next_page`, `section_continuous`를
받습니다. 문단 앞 나눔은 `pageBreakBefore`만 수정합니다. 구역 나눔은 양쪽에
본문이 있고 기존 구역 속성을 안전하게 복제할 수 있을 때만 삽입합니다. 새
구역은 번호를 이어가며 기존 머리글·바닥글 part를 공유합니다. 기존 구역 경계의
이동·삭제와 가져온 인라인 페이지 나눔 변경은 보호합니다.

### 인라인 그림 삽입

`update_image`는 현 리비전의 편집 가능한 문단 ID와
`image: { action: "insert", base64, alt, widthEmu }`를 받습니다.
본문 또는 단순 표 셀 문단 끝에 인라인 그림을 넣습니다. 폭을 생략하면
그림의 가로 비율과 최대 기본 폭을 사용합니다. PNG·JPEG, 최대 512 KiB,
8192px 한 변 및 1,200만 픽셀까지 허용합니다.

그림은 새로운 media part와 관계를 받습니다. 기존 media는 덮어쓰지
않습니다. [Open XML 인라인 그림 구조](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-insert-a-picture-into-a-word-processing-document)를 따릅니다.

브라우저의 `그림 편집`에서 로컬 파일과 대체 텍스트를 선택하고 적용한 뒤
저장합니다. 저장된 PNG·JPEG는 문서 세션과 현재 리비전에 연결된 이미지
진입점으로 표시합니다. HTTP는 외부 관계, SVG, 미지원 형식 또는 임의 패키지
경로를 제공하지 않습니다. 떠 있는 그림과 특수 배치의 원본은 유지합니다.

같은 도구에서 기존 인라인 PNG·JPEG를 선택하고 대체 텍스트를 바꾸거나
비운 뒤 저장할 수 있습니다. HTTP와 MCP는 현재 리비전의 그림 run ID와
`image: { action: "set_alt", alt }`를 사용합니다. 그림 파일·관계·크기·배치를
유지합니다.

기존 그림을 선택하고 `그림 삭제`를 누른 뒤 저장하면 인라인 그림이 사라집니다.
HTTP·MCP는 현재 그림 run ID에 `image: { action: "delete" }`를 적용합니다.
공유 그림의 손실을 막기 위해 그림 데이터와 관계는 패키지에 유지합니다.

기존 그림을 고른 뒤 너비를 pt로 입력하고 `비율 유지 크기 변경`을 적용합니다.
HTTP·MCP에서는 그림 run ID에 `image: { action: "resize", widthEmu }`를
사용합니다. 표시 크기와 변환 크기가 일치하는 인라인 PNG·JPEG에서 폭과 높이를
함께 변경하고 그림 파일·관계·설명을 유지합니다.

기존 그림과 로컬 파일을 고르고 `선택한 그림 교체`를 누른 뒤 저장합니다.
HTTP·MCP는 현재 그림 run ID에 `image: { action: "replace", base64 }`를
적용합니다. 교체는 잘리지 않고 효과가 없는 인라인 PNG·JPEG에 적용합니다.
표시 크기와 설명은 유지하고 새 media part 및 관계를 만들므로 기존 파일을
공유하는 다른 그림은 영향을 받지 않습니다.

기본 채우기와 사각형을 사용하는 인라인 PNG·JPEG를 선택하고 상하좌우의
자르기 비율을 백분율로 입력합니다. 서로 마주 보는 두 변의 합은 99% 이하여야 합니다.
HTTP·MCP의 `image: { action: "crop", crop: { left, top, right, bottom } }`는
0.001% 단위의 정수를 받습니다. 네 값을 모두 0으로 보내면 자르기를 해제합니다.
표시 영역의 바깥 크기와 그림 파일·관계·설명은 유지합니다.
[DrawingML 원본 자르기](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.sourcerectangle)를 사용합니다.

기본 인라인 PNG·JPEG는 `그림 180도 회전`으로 방향을 바꾸고
`그림 방향 되돌리기`로 복원할 수 있습니다. 크기, 원본 파일과 자르기 범위는 유지합니다.
HTTP·MCP는 `update_image`에 그림 run ID와 `image: { action: "rotate", rotation: 180 }`을
보냅니다. `rotation: 0`은 기본 방향으로 되돌립니다. 회전 뒤 자르기 비율은 원본
이미지를 기준으로 입력합니다. 다른 각도와 떠 있는 그림은 Word에서 편집할 수 있습니다.


일반 본문의 인라인 그림을 선택하고 `그림 번호와 캡션 삽입`을 적용하면 바로
다음 문단에 캡션을 넣습니다. Word는 SEQ 필드로 그림 번호를 계산합니다. 앞에
캡션을 추가하면 뒤따르는 지원 그림 번호를 다시 계산하고 그림 파일과 대체
텍스트는 유지합니다. HTTP·MCP는 그림 run ID와 캡션 텍스트를
`insert_picture_caption`에 보냅니다. 여러 그림이 한 문단에 있거나 복합 필드 및
기존 캡션을 확실히 구분할 수 없는 경우는 보호합니다.
[Word 캡션 번호](https://support.microsoft.com/en-gb/word/add-format-or-delete-captions-in-word)를 사용합니다.

### 인쇄와 PDF 저장

파일 작업의 `인쇄·PDF`는 저장된 문서를 브라우저 인쇄 창으로 보냅니다.
PDF가 필요하면 브라우저 인쇄 대상에서 PDF 저장을 선택합니다. 편집 도구,
활동 기록, 구역 안내문을 숨기고 본문·표, 표시 가능한 그림, 대표 머리글과
바닥글을 출력합니다. 용지 규칙은 구역의 크기와 여백을 사용하며 실제 출력은
브라우저와 프린터의 용지 지원에 따라 달라질 수 있습니다.

글꼴과 표시 가능한 그림이 준비되기 전에 인쇄 창을 열지 않습니다. 문서가
바뀌었으면 다시 인쇄하도록 안내합니다. 브라우저 인쇄 엔진이 줄과 페이지를
배치하며, 반복 표 머리행·연속 구역의 정확한 조판·쪽 번호 필드·Word 시각
일치·변경 표시 출력은 별도 검증 범위입니다.
[브라우저 인쇄 CSS](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing)를 사용합니다.

2026-11-12 macOS의 Chrome 157.0.8103.51에서 세로·가로 Letter 구역,
표와 인라인 PNG를 넣은 합성 DOCX를 확인했습니다. 편집기의 `인쇄·PDF`
버튼이 그림 로딩 뒤 인쇄를 요청하는지 확인하고, 같은 편집기 화면을 Chromium
PDF로 출력했습니다. CSS 용지 크기를 사용한 PDF는 세로 612×792 pt와 가로
792×612 pt 두 쪽이었습니다. 첫 쪽에 본문과 표 텍스트, 둘째 쪽에 본문과
PNG가 들어갔고 편집 도구 문구는 추출 텍스트에 없었습니다. 운영체제의 인쇄
대화상자와 Word 조판 비교는 별도 검증 범위입니다.


### 찾기와 바꾸기

`검색`에서 대소문자, 단어 단위, 본문 또는 표 범위를 설정할 수 있습니다.
같은 문단 안의 반복 결과와 서식 경계를 넘는 문자열도 검색합니다. 이전·다음
결과로 이동하거나 원하는 결과를 선택합니다.

한 건 또는 전체 바꾸기는 편집 가능한 결과에만 적용됩니다. 삽입한 글은
검색 결과 시작의 서식을 따르고, 검색 범위 밖의 내용과 서식은 유지됩니다.
전체 바꾸기는 한 번의 초안 변경으로 저장·실행 취소합니다. 오래된 결과와
200건을 넘은 일부 결과에는 전체 바꾸기를 허용하지 않습니다. 그림과 보호
구조를 가로질러 수정하지 않습니다. 주석·각주와 머리글·바닥글은 현재 범위에
포함되지 않습니다.

`문서 개요`는 본문 문단의 직접 또는 스타일 상속 개요 수준을 읽어 제목을
최대 200개 표시합니다. 제목을 선택하면 해당 문단으로 이동합니다. 현재
본문 커서보다 앞선 가장 가까운 제목을 표시하며, 미저장 텍스트와 스타일
변경도 반영합니다. 저장된 본문 북마크도 목록에서 선택해 해당 문단으로
이동할 수 있습니다. Escape로 개요를 닫으면 개요 버튼으로 초점이 돌아옵니다.
미리보기 페이지 번호를 입력하면 해당 페이지 시작으로 이동합니다. 번호는
명시적 나눔과 구역을 반영한 브라우저 미리보기 순서입니다. 주석과 변경 위치는
이 목록에서 다루지 않습니다.

### 링크·북마크·각주

`링크·북마크·각주·미주`에서 기존 웹 링크를 고르고 새 HTTP(S) 주소를 적용한 뒤 저장합니다.
HTTP와 MCP는 현재 링크 run ID와 `reference: { action: "set_link_url", url }`을
사용합니다. 링크의 표시 문구와 서식, 다른 링크가 공유하는 관계를 유지합니다.


`update_reference`는 현재 리비전의 편집 가능한 본문 문단 ID를 받습니다.
`reference.action`이 `insert_bookmark`이면 문단 끝에 이름이 있는 북마크
위치를 만듭니다. 북마크 이름은 영문자로 시작하는 영문자·숫자·밑줄 1~40자이며
대소문자만 다른 중복 이름도 거절합니다.

`insert_link`에는 표시 텍스트와 HTTP(S) 주소 또는 기존 북마크 이름 중
하나를 지정합니다. 사용자 인증 정보가 들어간 주소와 실행형·로컬 파일 주소는
거절합니다. 주소는 관계로만 저장하며 저장 과정에서 접속하지 않습니다.
[Open XML 북마크 쌍](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.bookmarkstart)을 따릅니다.

`페이지` 도구의 `북마크가 있는 문단 이동`을 열어 이동할 문단을 고른 뒤
앞뒤 문단과 순서를 바꿀 수 있습니다. 해당 문단 안에 시작과 끝이 있는
유일한 북마크와 문단 XML을 함께 옮깁니다. HTTP·MCP는 본문 문단 ID로
`move_bookmark_up` 또는 `move_bookmark_down`을 적용합니다. 표·페이지·구역
경계와 문단에 걸쳐 있는 북마크는 보호합니다.

편집기의 `링크·북마크·각주·미주`에서 편집 가능한 본문 문단을 골라 북마크, 웹 링크,
북마크 링크를 추가합니다. 적용하고 저장한 뒤 내부 링크를 누르면 해당 본문
문단으로 이동합니다. 웹 링크는 사용자가 선택할 때 별도 탭에서 열립니다.
표시 가능한 북마크는 최대 500개이며 중복되거나 쌍이 끊어진 북마크와 안전하지
않은 링크는 이동 대상으로 표시하지 않습니다. 미주와 필드 갱신은 남아 있습니다.

지원되는 기존 북마크를 선택해 이름을 바꾸면 해당 문단 표시와 내부 링크에
새 이름이 적용됩니다. HTTP·MCP의 `update_reference`는 북마크 문단 ID와
`reference: { action: "rename_bookmark", bookmark, newBookmark }`를 받습니다.
이름 변경은 단독 작업으로 저장합니다. 다른 story의 연결이나 복합 필드가
있으면 원본을 보호합니다.

`북마크와 내부 링크 해제`를 선택하면 북마크 표시를 삭제하고 해당 위치를
가리키는 내부 링크를 일반 텍스트로 바꿉니다. 표시 문구와 서식은 유지합니다.
HTTP·MCP는 북마크 문단 ID와 `reference: { action: "delete_bookmark", bookmark }`를
받습니다. 복합 필드와 다른 story의 참조는 보호합니다.

기존 링크에서 `링크 해제`를 적용하고 저장하면 표시된 글과 서식은 유지되고
클릭 동작만 사라집니다. HTTP·MCP는 링크 run ID에 `reference: { action: "unlink" }`를
사용합니다. 복잡한 구조는 보호하고 공유 관계는 남겨 둡니다.

다른 본문 문단의 `텍스트 상호 참조 삽입`에서 한 문단의 평문을 포함한 북마크를
선택하면 Word REF 필드가 추가됩니다. HTTP·MCP는 문단 ID에
`reference: { action: "insert_bookmark_ref", bookmark }`를 적용합니다.
브라우저에서 참조의 텍스트를 확인하고 대상 문단으로 이동할 수 있습니다.
북마크 이름을 바꾸면 지원 REF의 대상도 바뀝니다. 북마크를 지울 때는 해당
참조의 표시 글자를 남깁니다. 복합 필드나 다른 story의 참조는 보호합니다.
[Word 참조 필드 갱신](https://support.microsoft.com/en-us/word/some-fields-are-updated-while-other-fields-are-not)을 참고할 수 있습니다.

편집 가능한 본문 문단에서 `각주 삽입`을 선택하면 문단 끝에 각주를 연결합니다.
HTTP·MCP는 문단 ID에 `reference: { action: "insert_footnote", text }`를
적용합니다. 브라우저에는 참조 옆에 각주 내용을 표시합니다. 각주의 번호와
쪽 아래 배치는 Word가 계산합니다. 사용자 지정 번호와
미주는 지원 범위에 포함되지 않습니다.
[Word 각주 참조 규칙](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.footnotereferencemark)을 사용합니다.

편집 가능한 본문 문단에서 `미주 삽입`을 선택하면 문단 끝에 미주를 연결합니다.
HTTP·MCP는 문단 ID에 `reference: { action: "insert_endnote", text }`를 적용합니다.
미주 내용은 참조 옆에 표시하며, Word 미주 part와 번호 ID는 각주와 별도로 관리합니다.
`기존 각주·미주`에서 기본 번호와 한 문단의 평문을 포함한 미주를 골라 수정합니다.
HTTP·MCP는 미주 run ID에 `reference: { action: "set_endnote_text", text }`를 적용합니다.
미주 번호와 본문 참조, 다른 각주, 변경하지 않은 텍스트의 서식은 유지합니다.
`미주 삭제`는 한 곳에서 참조하는 평문 미주의 본문 마커와 해당 항목을
삭제합니다. HTTP·MCP는 미주 run ID에 `reference: { action: "delete_endnote" }`를
적용합니다. 다른 미주·각주·구분선, 공유 참조와 북마크 범위는 보호합니다.
복합 미주 편집은 Word에서 할 수 있습니다.
[Word 미주 규칙](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.endnotes?view=openxml-3.0.1)을 사용합니다.

`기존 각주·미주`에서 편집 가능한 각주를 고르면 한 줄 텍스트를 수정할 수 있습니다.
HTTP·MCP는 본문의 각주 run ID에 `reference: { action: "set_footnote_text", text }`를
적용합니다. 각주 ID와 본문 참조 및 다른 각주의 내용은 유지합니다.
복합 각주는 내용을 미리 볼 수 있습니다.

`각주 삭제`를 적용하고 저장하면 본문 참조와 그 각주가 함께 삭제됩니다.
HTTP·MCP는 각주 run ID에 `reference: { action: "delete_footnote" }`를
적용합니다. 다른 각주와 공유 참조, 구분선 및 관계는 보호합니다.

### AI 활동의 문단 위치

원본의 고유한 `w14:paraId`를 세션 안의 문단 위치 식별자로 사용합니다.
문단 위치가 달라져도 같은 ID가 확인되면 이전 활동에서 현재 위치로 이동할
수 있습니다. 같은 문서 part에서 중복되거나 잘못된 ID는 제외합니다.
[Word 문단 ID 규칙](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/a0e7d2e2-2246-44c6-96e8-1cf009823615)을 따릅니다.

문단 ID가 없는 경우 서버가 텍스트만 변경했다고 알린 인접 리비전에서만
위치 기준으로 비교합니다. 구조 변경, 누락된 리비전, 문단 삭제 또는 미저장
구조 초안에서 위치가 확인되지 않으면 이동 표시를 숨깁니다. 활동 표시와
별개로 모든 쓰기는 현재 리비전의 편집 ID로 검증합니다.

### 주석 검토

`검토`에서 저장된 주석을 읽고, 위치가 확인되는 본문 문단으로 이동할 수
있습니다. 내용이 있는 편집 가능한 본문 문단을 선택하고 주석을 적용한 뒤
저장합니다. MCP의 `add_comment`는 현 리비전의 문단 ID와
`comment.text`를 받습니다. 기본 범위는 문단 전체이며 Word 주석 part와
연결합니다. 주석은 UTF-8 4,000바이트, 목록은 최대 100개를 지원합니다.

본문 한 문단 안에서 일반 텍스트를 선택하고 검토 메뉴의
`선택한 텍스트에만 주석 달기`를 켜면 선택한 글자에 주석이 연결됩니다.
HTTP·MCP는 같은 문단의 `comment.startRunId`와 `comment.endRunId`를
받습니다. `startOffset`과 `endOffset`을 둘 다 지정하면 각 run 기준 UTF-16
범위를 사용하며 끝 위치는 주석 범위에서 제외합니다. 두 값을 생략하면
선택한 전체 run에 주석을 연결합니다.

주석을 단 문단의 내용은 수정할 수 있으며 범위를 없앨 수 있는 구조 조작은
보호합니다. [Word 주석 구조](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-insert-a-comment-into-a-word-processing-document)를 사용합니다.

기존 주석이 없는 문서에서 새로 주석을 작성하면 Word 확장 메타데이터가 함께
저장돼 작성 직후 답글과 해결 상태를 사용할 수 있습니다. 확장 정보가 없는
기존 주석과 Word의 별도 확장 형식은 그대로 보존합니다.

Word 확장 메타데이터에 고유하게 연결된 최상위 주석에서는 `주석 해결`과
`주석 다시 열기`를 적용할 수 있습니다. HTTP·MCP는 기존 주석 ID를
`targetId`로 보내고 `resolve_comment` 또는 `reopen_comment`를 사용합니다.
주석 본문·작성자·연결 범위·답글은 유지합니다. 확장 정보가 없는 주석에서는
본문과 위치를 확인할 수 있습니다.
[Word 확장 주석 상태](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/9660dacc-2ceb-4352-87d2-42ba1184f522)를 사용합니다.

같은 최상위 주석의 `답글 쓰기`에서 한 단계의 답글을 추가하고 검토 패널에서
상위 주석과 함께 봅니다. HTTP·MCP는 상위 주석 ID에 `reply_comment`와
`comment: { text }`를 보냅니다. 원래 주석의 범위와 해결 상태를 유지합니다.
확장 메타데이터가 없는 주석이나 이미 다른 주석에 달린 답글은 작성 대상에서 제외합니다.

검토의 `텍스트 변경 추적`에서 현재 본문 문단의 일반 텍스트 구간을 골라
교체 내용을 적용합니다. 새 텍스트를 비우면 삭제만 기록합니다. 저장하면 기존
텍스트는 삭제 변경으로, 교체 텍스트는 삽입 변경으로 기록되며 두 변경에 원래
서식과 작성자·시각이 유지됩니다. HTTP·MCP는 `track_run_text`에 현재 run ID,
정확한 `expectedText`와 새 `text`를 보냅니다. 서식 자체의 추적 변경이나
필드·북마크·주석을 포함한 보호 범위에서는 이 도구를 사용할 수 없습니다.

검토의 변경 추적 목록에서 기존 본문 텍스트 삽입·삭제를 하나씩
수락하거나 거절하고 저장합니다. HTTP·MCP는 현재 변경 run ID에
`accept_revision` 또는 `reject_revision`을 적용합니다. 유지한 텍스트의
서식과 관련 없는 변경은 보존합니다. 중첩 변경, 표, 문단 경계와 필드는
보호합니다. [Word의 변경 추적 규칙](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-accept-all-revisions-in-a-word-processing-document)을
따릅니다.

### 고급 개체

삽입 도구의 `수식`에서 `분수 삽입`을 선택하고 분자·분모를 입력한 뒤
저장합니다. [Office Open XML 분수](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.math.fraction?view=openxml-3.0.1)로 저장됩니다.
기존 분수는 `분수 바꾸기`에서 고른 뒤 분자와 분모를 바꿀 수 있습니다.
HTTP·MCP는 기존 수식 run ID에 `math: { action: "replace_fraction", fraction: { numerator, denominator } }`를 적용합니다.
분자·분모가 하나의 텍스트 run이고 별도 수식 속성이 없는 구조를 지원합니다.

| 개체 | 브라우저 표시 | 편집 | 외부 편집 |
| --- | --- | --- | --- |
| 단순 인라인 수식 | 수식 텍스트 | 삽입·교체·삭제 | Word 수식 개체 |
| 단순 분수 | 분자·분모와 가로 분수선 | 삽입·분자와 분모 수정 | Word |
| 행렬·중첩 분수 등 구조 수식 | 유형과 읽기 전용 표시 | 미지원 | Word |
| 도형·그룹·텍스트 상자 | 유형, 지원되는 상자의 텍스트 | 독립 상자의 평문 수정 | Word |
| 차트·SmartArt | 유형 | 미지원 | Word 또는 원래 연결 편집기 |
| 콘텐츠 컨트롤 | 유형과 인라인 평문 | 단순 평문 수정 | Word |
| 내장 개체·OLE | 유형 | 미지원 | 파일을 내려받아 신뢰할 수 있는 편집기에서 열기 |

수식의 `제곱근 삽입`에서 단순한 피제곱근을 입력해 Word 수식을 만듭니다.
`제곱근 바꾸기`는 기존 제곱근의 피제곱근만 바꾸고 수식 자리와 원본 서식을
유지합니다. HTTP·MCP는 `update_math`의 `math: { action: "insert_root", expression }` 또는
`math: { action: "replace_root", expression }`을 사용합니다. 제곱근은
[Word OMML의 숨은 근 차수](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.math.radicalproperties)를 따릅니다.

삽입의 `텍스트 상자 편집`에서 새 내용을 입력해 현재 본문 문단의 끝에
기본 인라인 텍스트 상자를 넣습니다. HTTP·MCP는 편집 가능한 본문 문단 ID와
일반 텍스트를 `insert_textbox`에 보냅니다. 저장한 상자를 같은 도구에서 선택해
평문을 수정할 수 있습니다. HTTP·MCP는 `update_textbox_text`에 상자 run ID, 현재
`expectedText`와 새 `text`를 보냅니다. 위치·크기·기존 서식을 유지하며 수정을
적용할 때 같은 내용의 DrawingML과 VML 호환 표현을 함께 편집합니다.
상자가 연결돼 있거나 호환 표현의 텍스트가 서로 다르면 읽기 전용으로 표시합니다.
[Word 텍스트 상자 구조](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/9ef316cc-3b39-4765-89ac-f8524fab383b)를 사용합니다.

삽입의 `콘텐츠 컨트롤 편집`에서 일반 본문 평문 컨트롤을 골라 텍스트를
바꿉니다. HTTP·MCP는 `update_control_text`에 컨트롤 run ID, 현재 문자열
`expectedText`와 새 `text`를 보냅니다. 컨트롤 ID와 원본 속성·서식은 유지합니다.
여러 텍스트 run이 있으면 공통된 앞뒤 문자열은 기존 서식 구간에 남고, 새로 입력한 부분은
변경 시작 위치의 서식을 따릅니다. 내용 잠금, 데이터 연결, 자리표시자와 복합 컨트롤은 보호합니다.
[Word 콘텐츠 컨트롤 구조](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.sdtcontentrun)를
사용합니다.

인식하는 인라인 개체는 본문에 표시하고 원본 XML과 관련 part를 보존합니다.
텍스트 상자와 컨트롤 표시가 원래 배치를 재현하지는 않습니다. 연결 데이터를
자동으로 읽거나 실행하지 않으며 OLE는 브라우저에서 열지 않습니다.

`수식` 도구 또는 `update_math`로 단일 `m:r/m:t`를 가진 인라인
`m:oMath`를 작성합니다. 행렬·분수 명령어를 해석하거나 계산하지 않습니다.
삽입은 현 리비전의 편집 가능한 문단, 교체·삭제는 편집 가능한 수식 run
ID를 대상으로 합니다. [Word 수식 구조](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.math.paragraph)를 사용합니다.

### 긴 문서의 입력과 검색

같은 텍스트 위치에서 750 ms 이내로 이어지는 입력은 첫 입력의 실행 취소
상태를 재사용합니다. 검색 패널은 화면이 짧아져도 내부를 스크롤할 수
있습니다. 페이지 가상화와 보조 기술·실제 모바일 입력기 검증은 남아 있습니다.
